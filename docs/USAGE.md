# Usage

Tokenomics is currently in early development. The implemented local CLI supports usage recording, deterministic analysis, privacy-safe loss recording, and measured outcome recording.

## Implemented CLI

```text
tokenomics init
tokenomics record
tokenomics analyze
tokenomics outcome
tokenomics report
```

### `tokenomics init`

Creates the local Tokenomics SQLite data store.

### `tokenomics record`

Records token usage without storing prompts or responses. Session identifiers are local UUID4 values generated by Tokenomics.

### `tokenomics analyze`

Runs deterministic local detectors against supplied text and optional token measurements. Use `--record-losses` to persist privacy-safe findings in the Token Loss Ledger.

### `tokenomics outcome`

Records the measured result of a recommendation after the user has tried it:

```bash
tokenomics outcome LOSS_ID --actual-tokens-saved 720 --accepted
```

Use `--rejected` when the recommendation was not accepted. Actual savings must be non-negative.

### `tokenomics report`

Produces a summary of locally recorded token usage.

## Findings

A finding should be understandable without reading a raw conversation. It should identify the pattern, evidence, estimated impact, confidence, and recommended action.

## Optimization workflow

Tokenomics should not silently rewrite or resubmit a user's request. The intended workflow is:

1. Detect a likely waste pattern.
2. Explain the evidence.
3. Estimate the potential savings.
4. Offer an optimization.
5. Let the user approve it.
6. Measure the resulting usage.
7. Compare actual savings with the estimate.
8. Store the outcome locally.

The `outcome` command now implements step 8 for recorded loss observations.

## Privacy

Running Tokenomics should not require uploading conversations or project data. See [PRIVACY.md](PRIVACY.md).
